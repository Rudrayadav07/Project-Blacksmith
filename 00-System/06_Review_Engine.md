# Project Blacksmith
## Engineering Evaluation Engine v1.0

---

# Purpose

Every completed mission is evaluated.

The purpose of evaluation is improvement.

Scores exist only to identify strengths and weaknesses.

The student is never compared against other students.

The only comparison is:

Yesterday vs Today.

---

# Evaluation Categories

Every mission receives scores in the following categories.

1. Problem Understanding

Can the student understand the problem before coding?

Score:
0–10

---

2. Planning

Did the student create a reasonable approach before implementation?

Score:
0–10

---

3. JavaScript Knowledge

Was JavaScript used correctly?

Variables

Functions

Arrays

Objects

Scope

Closures

Async

etc.

Score:
0–10

---

4. Engineering Thinking

Did the student:

Break the problem down?

Choose appropriate structures?

Think about trade-offs?

Score:
0–10

---

5. Code Quality

Evaluate:

Naming

Readability

Structure

Modularity

Maintainability

Score:
0–10

---

6. Debugging

Can the student locate and fix problems independently?

Score:
0–10

---

7. Testing

Did the student test:

Normal cases

Edge cases

Invalid inputs

Boundary cases

Score:
0–10

---

8. Optimization

Can the solution be improved?

Time Complexity

Space Complexity

Code Simplicity

Score:
0–10

---

9. Communication

Can the student explain:

Approach

Trade-offs

Complexity

Mistakes

Score:
0–10

---

# Final Score

Final score is NOT used for ranking.

Instead it determines:

Strengths

Weaknesses

Next Mission

---

# Performance Levels

90–100

Engineering Ready

Student demonstrates strong independent thinking.

---

80–89

Very Good

Minor improvements needed.

---

70–79

Developing

Good understanding.

Needs more consistency.

---

60–69

Learning

Fundamentals present.

Weak areas require focused practice.

---

Below 60

Foundation Required

Future missions adapt to strengthen weaknesses.

---

# Weakness Tracking

Every review updates:

Strengths

Weaknesses

Repeated Mistakes

Concepts Needing Revision

Interview Readiness

This becomes the student's Engineering Profile.

---

# Adaptive Rules

If:

Debugging < 6

↓

Increase debugging missions.

---

Communication < 6

↓

Increase interview missions.

---

Testing < 6

↓

Increase testing requirements.

---

Optimization < 6

↓

Introduce optimization challenges.

---

# Mission Completion

A mission is complete only if all of the following exist.

✓ Working Solution

✓ Manual Tests

✓ Explanation

✓ Reflection

✓ Git Commit

✓ Review

---

# Reflection Questions

At the end of every mission the student answers.

1. What was the hardest part?

2. What mistake cost the most time?

3. What concept became clearer?

4. What would I change?

5. What should tomorrow improve?

---

# Weekly Review

Every 7 missions:

Review strengths.

Review weaknesses.

Review progress.

Update engineering profile.

Adjust difficulty.

---

# Monthly Assessment

Instead of another daily mission,

the student completes an engineering assessment.

This includes:

Timed coding

Debugging

Code review

Interview

Feature building

Architecture discussion

---

# Graduation Criteria

The student graduates only when consistently able to:

Solve unfamiliar problems independently.

Write clean JavaScript.

Debug confidently.

Explain technical decisions.

Optimize solutions.

Build complete features.

Use AI responsibly.

Think like an engineer.

Completion of 90 calendar days alone does NOT guarantee graduation.

---

# Final Principle

The objective is not to complete the curriculum.

The objective is to become capable.
