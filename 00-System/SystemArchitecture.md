Project Blacksmith v1.0
System Architecture

This is the first and most important document.

Everything else will follow these rules.

1. Mission

Mission Statement

Project Blacksmith exists to transform a motivated Computer Science student into a software engineer who can independently think, design, build, debug, optimize, explain, and ship software using JavaScript as the primary language.

The goal is not to memorize JavaScript.

The goal is to build an engineer whose thinking remains valuable even as tools, frameworks, and AI evolve.

2. Primary Goal

After 90 days, the student should be able to:

Solve unfamiliar JavaScript problems.
Build small to medium applications without tutorials.
Explain technical decisions clearly.
Debug confidently.
Read and understand unfamiliar code.
Use AI as an engineering assistant rather than a dependency.
Perform strongly in JavaScript-focused technical interviews.
Learn new JavaScript frameworks significantly faster because of strong fundamentals.
3. Non-Goals

Project Blacksmith does not exist to:

Finish every JavaScript topic.
Memorize interview questions.
Complete random coding challenges.
Maximize the number of solved problems.
Copy AI-generated solutions.
Watch tutorials all day.

If an activity does not contribute to engineering ability, it does not belong in the program.

4. Core Philosophy
Principle 1 — Thinking Before Coding

Every problem must first be understood before any code is written.

No exceptions.

Principle 2 — Active Learning

Reading is never enough.

Every concept must be applied through code.

Knowledge without implementation is treated as incomplete.

Principle 3 — Productive Struggle

Struggling is part of the training process.

The objective is not to avoid mistakes.

The objective is to learn from mistakes.

Principle 4 — Build Before Consume

Before watching a solution,

attempt the problem independently.

Principle 5 — Explain Everything

If the student cannot explain:

why the solution works,
why an algorithm was chosen,
why an edge case matters,

then understanding is considered incomplete.

Principle 6 — Engineering Over Syntax

The program values:

reasoning,
architecture,
debugging,
decomposition,

more than remembering APIs.

5. Learning Model

Every mission follows the same pipeline.

Understand

↓

Analyze

↓

Plan

↓

Implement

↓

Test

↓

Debug

↓

Optimize

↓

Explain

↓

Reflect

Skipping steps is discouraged.

6. Daily Rule

Every day contains exactly one primary mission.

One mission.

One objective.

One measurable outcome.

Quality is more important than quantity.

7. AI Policy

AI is allowed only after independent effort.

AI may be used for:

reviewing code,
identifying bugs,
suggesting improvements,
discussing trade-offs,
explaining mistakes.

AI must never become the first attempt.

8. Difficulty Progression

Difficulty is determined by demonstrated competence.

The program adapts based on:

recurring mistakes,
confidence,
review scores,
explanation quality,
debugging ability.

Progression is earned.

9. Success Metrics

Progress is measured by improvement in:

problem decomposition,
implementation quality,
debugging speed,
optimization,
communication,
interview readiness,
engineering judgment.

Not by:

hours studied,
number of videos watched,
number of notes taken.
10. Engineering Values

The student is expected to develop:

curiosity,
discipline,
consistency,
ownership,
attention to detail,
willingness to refactor,
respect for clean code,
continuous improvement.
11. Final Outcome

Upon completion of Project Blacksmith,

the student should possess the habits and mental models expected from a strong entry-level software engineer.

The objective is to maximize long-term engineering ability rather than short-term memorization.

12. Motto

Think deeply. Build deliberately. Explain clearly. Improve continuously.
